# OPL Cloud 产品主说明

> 面向架构师、产品经理、设计/前端、后端和客户代表的共同入口。本文讲“用户得到什么”；11讲“页面怎样操作”；03/02讲实现契约；06讲Domain如何协作。所有内容使用同一F编号。
> 本文件是目标产品规格，不代表功能已经上线。D17中途调整套餐规则已由用户确认，详见第8节与13；已确定要求不再重复征求意见。

## 1. 这个产品做什么

OPL Cloud让用户选择或制作一个智能体，把它部署成可以持续访问的在线应用。用户不需要自己买机器、配置容器或手动注入模型密钥。

- **智能体**：能完成某类工作的AI应用，例如研究助手。可以选官方提供的，也可以上传自己制作的能力包。
- **版本**：某一次确定的智能体组合。旧版本不会因为官方发布新版而自动改变。
- **工作区（Workspace）**：用户选择套餐后获得的运行环境，有自己的名称、网址和付费周期。
- **Gateway**：提供模型调用、API密钥和用量信息。Token费用与工作区费用来自同一个获授权钱包主体，但分开显示。

你实际使用的是一个在线智能体，不需要认识OCI、Pod、Saga这些内部词。研发也不能把内部术语直接当按钮名称。

### 客户的一句话使用路径

**选智能体和版本 → 选套餐与模型 → 看清费用和规则 → 确认部署 → 看进度 → 打开使用。**

如果制作自己的智能体，先走：**上传能力包 → 选择界面 → 构建成功 → 得到可部署版本**，然后进入同一部署流程。

## 2. 谁可以做什么

| 身份 | 主要任务 | 边界 |
|---|---|---|
| 普通成员 | 使用获授权的工作区，查看本租户可见Agent/构建/用量，协作维护允许的包 | 不能因看到按钮或知道ID就获得购买、成员管理、账单主体或平台权限 |
| 租户管理员 | 管理本租户分组，上传/构建，部署/更新/续费/删除工作区 | 不访问其他租户私有数据，不管理平台运行底座和价格 |
| 租户所有者 | 上述任务及成员角色、最后所有者保护等租户治理 | 不自动成为平台管理员 |
| 平台管理员 | 开通/停用/重新启用租户，准入运行底座/界面、套餐政策和实例证据 | 真实生产变更、采购、退款仍通过对应授权边界；UI不是生产发布旁路 |

每个人用自己的Gateway身份登录，不共享租户钱包账户密码。账单主体与个人登录身份是两件事。一个用户初期只加入一个活动租户。

## 3. 用户在什么位置找到功能

客户主导航固定为：**概览、智能体、工作区、OPL Gateway、费用**。

- 智能体：官方/我的智能体、版本、上传、构建记录。
- 工作区：列表、新建、详情、模型配置、部署记录与维护操作。
- OPL Gateway：服务信息、模型用量、API密钥。
- 费用：订阅周期与独立的交易记录。
- 成员、分组和个人账户放设置/账户入口，不再每个内部Domain各占一个主菜单。
- 平台管理员有独立管理入口，不与普通客户的部署入口混排。

同一个工作区从列表、账单、操作详情进入时，展示同一份身份、状态和费用事实。不能各页面再起一套“成功/运行中”的定义。

## 4. 全部业务场景及客户验收

| F编号 | 用户要完成什么 | 系统应该怎样响应 | 怎样才算完成 |
|---|---|---|---|
| F01 登录与成员 | 用个人身份进入租户，邀请/调整授权成员 | 先验证Gateway身份，再确认租户权限；角色变更实时影响新动作 | 自己能进入；别人不能借ID越权；退出后页面清空个人敏感状态 |
| F02 分组与可见性 | 找到官方Agent，管理自己的私有Agent | 官方可选、私有隔离；归档分组禁止新写但不毁历史 | 只能看到有权看的，归档不误删正在使用的内容 |
| F03 平台目录 | 管理员提供可用Runtime、WebUI、资源套餐与价格 | 先准入真实制品和兼容契约，官方与第三方发布空间分开 | 客户看到的选项确有执行依据，不是手填一个“可用”标记 |
| F04 上传能力包 | 上传首次包或新版本并选择界面 | 检查实际文件，显示上传进度与明确的下一步 | 上传确认后才可创建构建任务，不把“传完了”当“能部署了” |
| F05 构建 | 查看阶段/日志，失败后重新构建 | 后台独立执行；刷新不会再创建一次任务；重试保留原记录 | 成功版本能在智能体详情被选择；失败有原因且不假称退款 |
| F06 版本管理 | 查看、更新、归档或下架一个版本 | 下架检查引用，已使用的版本不可直接清除 | “从目录移除”不说成“镜像字节已销毁”；历史保留 |
| F07 选择与报价 | 选定Agent、计算/存储套餐、模型 | 校验兼容性和容量，展示确定费用、账期、政策、报价有效时间 | 用户能够复述自己买了什么、付多少、何时到期 |
| F08 确认部署 | 点一次确认，得到能打开的在线应用 | 依次确认原单、密钥、资源、运行和证据，显示真实进度 | 不只资源开好了，当前应用也实际可用，才给“打开工作区” |
| F09 使用和配置 | 找工作区、打开、切换允许模型 | 当前配置与正在应用的配置分开显示 | 新模型被运行实例确认加载，而不只是表单保存成功 |
| F10 手动更新 | 选择新Agent版本，失败时恢复原运行版本 | 先检查数据兼容，验证新实例再切换；不自动跟随latest | 原购买历史不变，数据满足发布契约，新/旧路由结果明确 |
| F11 调整套餐 | 改计算或存储规格 | 升级确认后执行并保留原到期日；降配预约下期，先显示补差/目标价与影响 | 升级实际资源/运行确认后生效，降配不提前减资源、不退当期、下期只扣目标价 |
| F12 续费与到期 | 续费、补款后恢复使用 | 按原周期去重；余额不足明确提示，到期停止未付费使用 | 没有重复扣费；真实资源/运行恢复后才显示可用 |
| F13 删除与退款 | 删除工作区并了解数据/退款结果 | 二次确认破坏范围，逐项确认资源不存在，再处理有依据的原单退款 | “已删除”和“退款确认中”可并列；不是一条模糊的成功通知 |
| F14 Gateway | 查钱包、Token费用、Key和个人用量 | 所有余额/Key事实来自Gateway；明文Key只在授权的一次性展示出现 | 不泄露密钥；不把资源费与Token费混成难以核对的一笔 |
| F15 租户管理 | 暂停企业访问、重新启用或删除后恢复授权 | 停用可单独重新启用，并恢复原停用、仍已付且原资源存在的工作区；删除后15天恢复是另一条流程 | 误停不需要先删工作区；恢复租户不冒充恢复已销毁的数据 |
| F16 历史迁移 | 老客户继续使用已有资源或已有应用 | 保留原ID、原单、账期、Key、镜像和数据绑定 | 不因为升级平台而重扣、重买、重新构建或丢历史 |
| F17 运维证据 | 管理员知道哪里未完成、谁负责处理 | 读取原操作和原证据，明确下一步允许动作 | 没有证据时显示未验证，不把源码测试当上线成功 |

## 5. 六个实际用户故事

### 故事A：普通客户使用官方智能体

小林进入智能体页，选择“研究助手”的一个可用版本，点击“部署”。先选计算和存储套餐，再选允许模型；右侧确认区显示费用、周期和数据规则。小林确认一次后看到部署阶段，可以离开。回来仍是同一个操作。应用就绪后点击“打开工作区”，进入真实应用而不是空壳机器页面。需要应用自己的登录时，所有者可按既有授权入口一次性查看所声明的应用管理员凭据；不会把Gateway Key或应用会话密钥当登录密码展示给普通成员。

验收：所选版本、套餐、报价、扣款与最终应用对应同一Workspace；后台响应丢失不能产生第二次购买。（F07/F08/F09）

### 故事B：客户上传自己的智能体

小林用OMA生成能力包，在“我的智能体”创建一个版本，选择文件上传。上传中断后重新选择相同文件可继续未完成部分；不同文件不能覆盖同一个已确认版本。上传校验通过，再选择批准的界面并提交构建。构建失败可以查看原因和显式重试，原任务不消失。成功后版本出现在列表，再按故事A部署。

验收：关闭浏览器不取消已接受的构建；上传未完成不能构建；选择的界面确实进入构建产物。（F04/F05/F06）

### 故事C：已扣费，但部署暂未确定

客户看到“结果正在核实”，并分别看到付款、资源、应用的状态。页面不会建议再次点击购买。后台按原交易和原资源请求查询；可以继续交付时继续原操作，确定无法交付时才进入有证据的释放/退款过程。

验收：页面不能把timeout当作未扣费，也不能先承诺退款已到账。（F08/F13/F17）

### 故事D：手动更新智能体

工作区提示有新版本，但原版本继续运行。客户主动打开更新页，看到版本变化、数据兼容及可能中断。新实例未被验证之前不显示更新成功；不能安全迁移的数据拒绝更新。允许回滚的情形需确认旧运行版本和访问路由恢复，不能只改页面标签。

验收：不重新收取已有工作区购买费；持久数据与已接受套餐事实保持。（F10）

### 故事E：删除环境，不删除制作成果

删除确认框列出运行应用、计算、存储和数据可能不可恢复；同时明确已上传Package、构建历史和Agent版本保留。客户输入工作区名称确认。资源删除后可以看到“环境已删除，退款确认中”。退款核实完成才显示对应金额与记录。

验收：镜像下架、工作区删除、租户删除三类动作的范围不能互相代替。（F06/F13/F15）

### 故事F：老客户迁入新产品

只有资源、尚未装应用的旧工作区显示“资源已开通，待部署应用”。客户在原资源上选择Agent，不重新购买。已有应用的工作区继续显示现有版本/网址/数据；平台迁移不悄悄给它换成默认Agent。旧订阅没有新Quote也是合法历史，不制造客户从未接受过的报价。

验收：原ID、资源、Key、账期、购买凭证和应用数据可逐项核对。（F16）

## 6. 费用、数据与失败的统一承诺

- 钱包余额与Token用量认Gateway；Cloud工作区套餐价格认已接受的报价快照。不得复制第二个可花费钱包。
- 所有金额显示币种和周期，前端不重算业务价格。金额只是演示时必须标“示例”。
- 新版本不自动部署；上传不等于构建完成；资源开通不等于应用可用；HTTP202不等于业务成功。
- 未知结果先核实，不重复扣款、不盲目退款、不重复采购。
- 工作区删除与退款分开；版本下架不等于物理字节清除。
- 租户停用可重新启用；删除后15天恢复只恢复租户及保留资产权限，不恢复已经删除的CVM/CBS。
- 不承诺几分钟完成、无限容量、未经证明的数据保留期或零停机。
- 既有自动续费/人工续费义务按原订阅迁移，不因新UI重新设默认；新订阅续费授权由明确政策与客户选择决定，不从“按月”猜测授权。确认页展示真实周期起止；到期后恢复不当然从恢复当天再送完整新月。

## 7. 范围和非目标

本期交付F01–F17，不是公共Marketplace、任意容器托管平台或用户随意接入任意镜像的控制台。普通用户不选Runtime版本、不操作云厂商资源、不传provider凭据。管理员可准入符合契约的第三方Runtime，必须独立发布空间、明确版本与兼容性。

产品既保留普通用户的简单路径，也保留后台严谨的领域边界。不能因为客户只点一个按钮就把钱包、资源、编排、证据合并到一个服务；也不能把每条内部lane都拆成独立服务。

## 8. 已确认的套餐调整规则

用户已确认：**中途升级立即执行、保留原到期日，按剩余已付周期补差；降配下个账期生效，不退当期费用。**

这里说的是资源套餐，不是Agent版本更新；版本更新不会被暗中当成升配收费。客户会看到两个不同操作：

- **立即升级**：看清固定有效报价、补差、原到期日和可能中断后提交。进度分受理、补差确认、资源调整、运行检查。只有实际成功才显示新套餐已生效，不能点按钮就改成成功。
- **预约降配**：显示目标下一期价格与原到期日。当前周期仍用旧套餐，不退差、不提前降资源。新一期支付授权有效后执行；手动续费未付款时计划等待付款，不擅自开启自动扣费。

例如20美元/月升40美元/月且剩半个已付周期，补差10美元，原到期日不变。连续升配以最近已成功生效的套餐为基准，不重复计算已经支付的差额。更小的CBS磁盘不在普通降配支持范围，页面明确拒绝而不是假缩容。

执行失败和结果未知分开：未知先核实原单与原资源动作；确定失败按原补差单补偿，并明确实际资源状态，不能为了声称回滚而删除数据。未来删除时基础订单与升级补差按各自原政策/覆盖区间结算。

所有输入字段、公式精度、预约取消、账期边界、失败及并发验收由13统一规定；不再留下由前后端自行选择的收费规则。

## 9. 交给每个角色时怎样读

1. **所有人先读本文件**，按F编号确认用户结果，不必先看数据库。
2. **产品/客户代表**：打开离线交互原型和11，按故事A–F走一遍正常/失败路径。
3. **前端/设计**：11页面规格→04字段/动作映射→03生成类型；布局和业务状态不能另起词汇。
4. **后端**：06同一F的跨Domain顺序→03/proto→02落库字段→验证反例。
5. **架构师**：01边界→06因果/事务/权威读回→09迁移→08分工和验收。

每个工程任务必须带F编号、页面/operationId、Owner表和成功/失败证据。客户看到的承诺与后端实际终点不一致，就不能验收。
