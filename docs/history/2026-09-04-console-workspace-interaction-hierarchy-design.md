# Console Workspace 交互层级设计 UX-03E-B

Date: 2026-09-04

State: proposed design record

## 目标与边界

UX-03E-B 将 UX-03E-A 的 Workspace 列表、开通、详情运行时审计转换成可实现的交互层级。目标是让客户沿着已经跑通的业务链完成任务，而不是重新设计 Workspace 业务。

```text
列表：找到工作空间 → 进入
开通：选择套餐 → 核对价格 → 确认 → 开通 → 等待权威回读
详情：确认可用 → 打开 → 获取凭据 → 管理续费/预算 → 必要时删除
```

本设计不改变 Workspace、Fabric、Gateway、Wallet、Billing、Sub2API、权限、Secret、Control Plane API、DTO 或持久化边界。

## 输入证据

- UX-03E-A：`docs/history/2026-09-04-console-workspace-page-ui-audit.md`
- 运行时视口：桌面 `1280×900`，移动 `390×844`
- 当前 Workspace 业务链和控制器已在 UX-02A 及既有 Workspace browser suites 中验证
- Gateway Key 已完成 UX-03D 结果优先基线，可作为同一 Console 的交互参考

## 设计原则

1. **任务结果优先**：先回答客户能否找到、开通或进入 Workspace，再展示配置和诊断。
2. **动作后果分层**：打开、凭据查看、管理、维护、删除不能使用同一视觉权重。
3. **权威状态不猜测**：可用性、报价、Runtime URL、开通结果和删除结果继续由现有 owner readback 决定。
4. **技术证据后置**：`Workspace ID`、`Runtime URL`、`operation ID`、原始状态和 checks 默认隐藏，只在技术详情中披露。
5. **移动端可达**：首屏优先展示当前任务和主动作，所有触控目标不小于 `44×44px`，不靠横向滚动承载操作。
6. **不为美观删除业务事实**：报价构成、确认、失败/待确认、凭据生命周期和删除确认必须保留。

## 总体层级

```text
L0 页面身份：工作空间
L1 当前业务结果：找到 / 可用 / 应付金额 / 可进入
L1 页面主动作：新建工作空间（列表）或打开工作空间（详情）
L2 高频动作：进入详情、刷新、查看/复制凭据、核对开通信息
L3 管理：轮换密码、自动续费、预算设置
L4 维护：重置总额度用量、重置滚动窗口用量
L5 高风险：删除工作空间
L6 辅助/技术：分页、价格构成、余额、计费周期、开通阶段、Runtime/operation/checks
```

## Workspace 列表页

### 任务与顺序

```text
页面标题与身份
→ 工作空间总数
→ 新建工作空间（主按钮）
→ Workspace 列表结果
→ 名称、套餐/存储、当前可用状态、权益截止
→ 明确的查看详情/进入入口
→ 分页
```

### 桌面规则

- 保留高密度列表；
- 名称作为主要识别信息；
- 当前状态值直接可见，弱化“生命周期状态”这类字段元语言；
- 右侧进入入口需要有可理解的文字或可访问名称，不能只依赖箭头；
- 新建按钮保持页面级主动作，不与单行进入混淆。

### 移动规则

- 继续使用纵向卡片，不引入横向滚动；
- 卡片第一层显示名称、状态、套餐/存储、权益截止；
- 进入详情应有明确的触控入口，整行可点击可以保留，但不能只依赖图标理解；
- `390×844` 下优先让列表结果和新建入口可见。

## Workspace 开通页

### 任务与顺序

```text
返回列表
→ 配置 / 核对 / 开通状态步骤
→ 名称
→ 套餐选择
→ 实际应付金额
→ 价格构成（计算、存储）
→ 开通方式、计费周期、续费
→ 明确确认
→ 一次提交
→ 开通阶段与结果
→ 查看工作空间 / 刷新状态
```

### 交互规则

- `核对开通信息` 是配置阶段的下一步，不直接产生开通；
- 确认阶段必须显示名称、套餐、价格版本、计费周期、自动续费和确认勾选；
- 只有明确确认后才允许提交；
- 预付金额、客户权益、余额不足、报价不可用保持现有语义，不转成猜测或隐藏；
- 成功结果必须等待 Workspace 和 Runtime 权威回读后才进入可打开详情；
- 结果未知、多个未完成操作或回读不可用时，页面只提供重新检查，不提供重复购买入口；
- operation、phase、checks、errorCode 等保留在技术详情，不成为客户主路径标题。

### 移动规则

- 订单摘要紧跟套餐选择和实际应付金额，避免用户滚动后才看到价格；
- 主提交按钮保持整行宽度和至少 `44px` 高度；
- 步骤条可压缩但不得隐藏当前阶段；
- 不删除计算/存储价格构成，只调整呈现顺序。

## Workspace 详情页

### 任务与顺序

```text
返回列表
→ 名称与客户可理解的可用性
→ 打开工作空间（主按钮）
→ 刷新
→ 套餐、实际月费、权益截止
→ 访问凭据
   → 登录账号
   → 登录密码：显示/复制
   → Workspace API 密钥：显示/复制
   → 轮换密码
→ 续费与存储
   → 自动续费
   → 持久存储
→ 高级设置
   → 预算配置
   → 预算用量重置
→ 删除工作空间（独立高风险区）
→ 技术详情
```

### 详情动作分层

- **打开**：最高优先级，只在 Runtime 权威 URL 可打开时启用；
- **查看/复制凭据**：高频但敏感，直接可见，默认遮罩，显式 reveal；
- **刷新**：辅助高频动作，重新确认当前页面事实；
- **管理**：轮换密码、自动续费、预算设置；
- **维护**：重置总额度和滚动窗口用量，保持两项语义独立；
- **删除**：独立于预算，使用危险样式、确认、幂等和权威回读；
- **技术详情**：默认关闭，只承载诊断和原始字段。

### 移动规则

- 身份卡片先给出可用性和打开按钮；
- 打开按钮和刷新按钮使用至少 `44×44px` 触控目标；
- 凭据区按“登录入口”和“API 调用”两个目的组织，但不改变已有字段和 Secret owner；
- 高级设置默认关闭，删除不能与预算设置使用同一标题或同一视觉组；
- 固定底部导航存在时，展开设置或删除区域不能被遮挡；
- 页面底部保留安全间距，确保最后一个高风险动作可见。

## 业务动作映射与不可变边界

| 用户动作 | 现有业务映射 | 不变边界 |
| --- | --- | --- |
| 新建工作空间 | 导航到 `/console/workspaces/new` | 不新增 API |
| 核对开通信息 | `WorkspaceLaunchController.reviewWorkspaceLaunch()` | 不产生 Launch 写入 |
| 确认预付并开通 | `submitWorkspaceLaunch()` | 保留 CSRF、幂等键、报价和回读 |
| 查看工作空间 | Workspace 权威列表/详情回读 | 不使用未确认 DTO 猜测入口 |
| 打开工作空间 | Fabric Runtime 权威 URL | 不改 Fabric owner |
| 显示密码/API Key | Workspace Secret Controller reveal | 页面内存、互斥显示、60 秒隐藏 |
| 轮换密码 | Secret Controller mutation | 不改变凭据所有权 |
| 自动续费 | Workspace Renewal Controller | 不改变续费状态机 |
| 保存/重置预算 | Workspace Budget Controller | 不新增 Wallet 或预算 owner |
| 删除工作空间 | Workspace Delete Controller | 保留确认、幂等、回读和不可逆警示 |

## 客户语言与技术语言

默认客户层使用：

- 工作空间；
- 当前可用 / 暂不可用 / 正在确认；
- 打开工作空间；
- 访问凭据；
- 续费与存储；
- 预算设置；
- 删除工作空间。

技术详情可保留权威字段原名并提供上下文：

- `Workspace ID`、`Runtime ID`、`Runtime URL`；
- `operation ID`、`phase`、`checks`；
- `priceVersion`、原始 lifecycle/renewal/budget status；
- source reason 和错误码。

不能把技术字段伪装成客户状态，也不能因中文化而改变合同字段含义。

## UX-03E-C 最小实现写集

只允许在以下范围内实现已批准的层级：

- `apps/console-ui/src/pages/CustomerPages.tsx`：列表、开通、详情的结构和客户文案；
- `apps/console-ui/src/styles.css`：Workspace 列表、开通、详情的布局、分组和移动断点；
- `tests/ui/workspace-task-experience-browser.test.ts` 及必要的 Workspace focused browser tests；
- `docs/history/**`：实现和验证记录。

不修改：

- Workspace、Fabric、Gateway、Wallet、Billing、Sub2API API/DTO/合同；
- Controller 状态机、请求顺序、幂等、回读、权限和持久化；
- OPL 图标资产；
- 其他页面，除非 focused regression 证明共享样式改动产生直接影响。

## UX-03E-C 验收条件

### 列表

- 桌面和移动端都能清楚识别 Workspace、套餐、状态、权益截止；
- 进入详情的语义不只依赖箭头；
- 新建入口保持主动作；
- 空、不可用、错误、分页语义不变；
- 无横向溢出。

### 开通

- 配置、核对、开通状态步骤清晰；
- 实际应付金额在移动端不被推到次要位置；
- 无确认不能提交；
- 未知/冲突/失败状态不出现重复购买入口；
- 技术证据默认隐藏。

### 详情

- 可用性和打开动作优先；
- 凭据默认隐藏，显示/复制可达，60 秒策略不变；
- 预算、维护、删除分组清楚；
- 删除独立并保留确认和回读；
- 技术详情默认关闭；
- 固定底部导航不遮挡操作。

### 共同

- 桌面 `1280×900`、移动 `390×844` 双视口验证；
- 无 page error、应用 Console error、外部请求和横向溢出；
- focused browser tests、typecheck、lint、build 和 `npm run verify:local` 通过。
